# Denoising Diffusion Probabilistic Models (DDPM) — Reproducible Workflow

This repository implements DDPM image generation in PyTorch, extended to support class-conditional training and sampling on CIFAR-10. The project builds on the original work by **Alokia**, retaining configurable UNet/backbone options while adding job scripts and guides for running on SLURM clusters or locally.

## 1. Environment Setup
1. Clone the repository and enter it.
   ```bash
   git clone <repo-url>
   cd diffusion-DDPM-pytorch
   ```
2. Create and activate an isolated Python environment (recommended).
   ```bash
   conda create -n ddpm python=3.10 -y
   conda activate ddpm
   ```
3. Install the required packages (Torch wheels hosted on the PyTorch index).
   ```bash
   pip install -r requirements.txt --extra-index-url https://download.pytorch.org/whl/cu121
   ```

## 2. Configuring Training
All knobs live in `config.yml`:
- `run_name`: unique tag so checkpoints save as `checkpoint/<run_name>.pth` and resume cleanly.
- `Model`: UNet architecture (channels, attention, heads, `num_classes`).
- `Dataset`: choose `mnist`, `cifar`, or `custom`; set paths, image size, and loader options.
- `Trainer`: diffusion horizon `T` and beta range.
- `Callback`: checkpoint frequency and location.
- `consume` / `consume_path`: resume training from an existing checkpoint.

Key CLI equivalents:
- `train.py` consumes the config directly.
- `train_ddpm.sh` wraps `train.py` for SLURM. Update `PYTHON_PATH` to your environment, adjust `SBATCH` directives, and ensure `run_name` is set before submission.

## 3. Running Training
Minimal single-GPU run:
```bash
python train.py
```
SLURM job (after editing the script variables):
```bash
bash train_ddpm.sh
```
Monitoring tools:
- `logs/training_status.log` records job metadata.
- `check_training.sh` tails SLURM queues, recent checkpoints, and optional `logs/monitor_progress.py` output (auto-generated by `train_ddpm.sh`).

## 4. Sampling & Evaluation
### Command-Line Interface
The generator accepts class-conditional prompts:
```bash
python generate.py \
    -cp checkpoint/<run_name>.pth \
    --class_name dog \
    -bs 16 \
    --result_only \
    --nrow 4 \
    --show
```
Arguments of interest:
- `--class_name {airplane, automobile, bird, cat, deer, dog, frog, horse, ship, truck}`
- `-bs/--batch_size`: number of samples.
- `--result_only`: skip intermediate denoising frames.
- `--interval`: stride for saving intermediate grids when `--result_only` is omitted.
- `--to_grayscale`: optional grayscale conversion for previews.

### Batch Generation via SLURM
`generate_ddpm.sh` mirrors the training script. Edit:
- `CHECKPOINT_PATH` to the desired checkpoint.
- `--class_name` arguments (the script lists all CIFAR-10 classes for quick copy/paste).
- `PYTHON_PATH` if you use a different virtual environment.
Launch with:
```bash
bash generate_ddpm.sh
```

### Legacy Examples
The original repo showcased checkpoints for MNIST, CIFAR-10, and CelebA-HQ. Once trained, similar commands still apply, e.g.:
```bash
python generate.py -cp "checkpoint/cifar10.pth" -bs 16 --interval 50 --show -sp "data/result/cifar10_sampler.png"
python generate.py -cp "checkpoint/cifar10.pth" -bs 256 --show --nrow 16 --result_only -sp "data/result/cifar10_result.png"
```

## 5. Continuation & Checkpointing
- Resume training by setting `consume: True` and pointing `consume_path` to the previous checkpoint.
- `ModelCheckpoint` saves every `save_freq` epochs; continuing runs reuse the formatted `run_name` paths to avoid overwriting.
